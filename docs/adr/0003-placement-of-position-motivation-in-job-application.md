# ADR-0003: 志望動機（PositionMotivation）の JobApplication 集約への配置

- **ステータス**: 承認 (Accepted)
- **決定日**: 2026-10-17

## コンテキスト (Context)
志望動機（なぜその企業・そのポジションを受けたいのか）は、「企業（TargetCompany）」に紐づくのか、それとも「応募（JobApplication）」に紐づくのかという配置先を検討した。

## 決定事項 (Decision)
志望動機は「ポジション（職種・役割・事業部）ありき」であるというドメイン洞察に基づき、`PositionMotivation`（値オブジェクト）として **`JobApplication` 集約直下** に配置する。

- `PositionMotivation` の属性:
  - `primaryReason`: 志望理由の中核
  - `appealPoints`: 自身の強み・提供価値のアピールポイント（配列）
  - `careerAlignment`: キャリア目標との整合性
  - `companySpecificFactor`: その企業・事業ならではの要因（任意）

## 影響とトレードオフ (Consequences)
- **メリット**:
  - 同一企業であっても「バックエンドエンジニア」と「エンジニアリングマネージャー」など、異なる職種・異なる事業部に応募する際に、それぞれ完全に独立した志望動機と訴求ポイントを管理できる。
  - 値オブジェクトとして不変性を保ち、更新時は集約ルートのメソッド経由で安全に置き換えられる。
- **トレードオフ**:
  - 企業全体のビジョンへの共感など共通項がある場合、別応募への動機入力時に自動転記するなどのUI/アプリケーション層での補助が必要になる。
