# ADR-0013: 登録済み志望企業と確定面接の訂正

- **ステータス**: 承認 (Accepted)
- **決定日**: 2026-10-20

## コンテキスト (Context)

志望企業と確定済み面接は、登録後に事実が変わる。企業名や事業概要の訂正、ミーティング URL や対面場所の差し替え、開始時刻の変更がそれに当たる。これまでは新規登録と、面接の開始・終了だけを変える `reschedule` があり、企業プロフィールの更新メソッドは企業名を変えず、画面からも呼べなかった。

訂正で壊してはならないものは次のとおり。

- 企業 ID を参照している選考応募。企業を消すと参照が切れる。
- 面接セッション ID、その面接が属する選考、登録時のステージ。準備タスクの種類はステージから作られている。
- 完了済み面接の記録と、完了済みタスクの期限。
- 逆質問ストックと、面接へ割り当て済みの逆質問スナップショット。
- 返答待ちの候補日。候補日は取り下げてから出し直す。

## 決定事項 (Decision)

訂正は二つの操作に限る。削除はどちらにも含めない。

### 1. 志望企業の訂正

`TargetCompany.revise(name, profile)` で企業名と `CompanyProfile` をまとめて差し替える。企業 ID と逆質問ストックは変えない。

- 企業名は空にできない。プロフィールの必須条件は新規登録と同じ。
- ドメインイベントは `TARGET_COMPANY_REVISED`。読み取りモデルはこのイベントで企業と、その企業を参照する選考の表示名を更新する。
- API は `PATCH /api/companies/{companyId}`。本文は新規登録と同じ項目。

### 2. 確定面接の訂正

`JobApplication.reviseInterview` で、未完了の `InterviewSession` について開始・終了、`InterviewFormat`、面接官名をまとめて差し替える。セッション ID、ステージ、割り当て済み逆質問、振り返りは変えない。

- 完了済みセッションは訂正できない。
- 重複判定は新規登録と同じ移動・準備バッファを、訂正後の形式で計算する。対象セッション自身は比較から外す。
- そのセッションに紐づく未完了 TODO の期限は、新しい開始時刻に合わせる。完了またはスキップ済み TODO の期限はそのまま。
- 既存の `reschedule` は開始・終了だけの API として残す。こちらも未完了 TODO の期限は同じ規則で合わせる。
- ドメインイベントは `INTERVIEW_SESSION_REVISED`。
- API は `PATCH /api/applications/{applicationId}/interviews/{sessionId}`。ステージは受け取らない。

選考エントリーの職種・志望動機、逆質問の文言、候補日の中身、企業と面接の削除は、この決定の対象外とする。

## 影響とトレードオフ (Consequences)

- **メリット**:
  - 登録時の入力ミスと、その後の URL・場所・時刻の変更を、集約の ID を保ったまま訂正できる。
  - 形式を対面へ変えたときの移動バッファも、新規登録と同じ衝突規則で再検証できる。
  - 企業名の訂正が表示中の選考へ反映される。
- **トレードオフ**:
  - ステージを変える訂正はできない。ステージが違う面接は、あらためて登録する。
  - 完了済み面接の内容は訂正できない。記録の修正が必要になった場合は別の決定にする。
