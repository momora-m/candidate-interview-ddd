# ADR-0001: 候補者（求職者自身）視点でのドメインモデリングへの転換

- **ステータス**: 承認 (Accepted)
- **決定日**: 2026-10-17

## コンテキスト (Context)
当初は企業の人事・採用担当者が利用する採用管理システム（ATS: Applicant Tracking System）のドメインモデル（候補者を評価・選考するモデル）を想定していた。
しかし、本アプリケーションの本来の利用主体は「転職・就職活動を行う候補者本人（求職者自身）」である。

利用主体が採用担当者から候補者本人へ変わることで、管理すべき関心事・不変条件（Invariants）・ユビキタス言語が根本から変化する。

## 決定事項 (Decision)
ドメインモデルの中心を「候補者を評価・管理するシステム」から、**「候補者が複数企業の選考プロセス、面接日程、逆質問、事前準備TODO、および面接後の振り返りインサイトを管理するパーソナルキャリア管理システム」**へと完全に再定義する。

- 中心概念を `Candidate`（被管理対象）から、自身が主体となる `JobApplication`（応募エントリー）および `TargetCompany`（志望企業）へ変更。
- スケジュール重複の関心事を「面接官のダブルブッキング」から「自身の他社面接との衝突および移動時間の過密防止」へ変更。

## 影響とトレードオフ (Consequences)
- **メリット**:
  - ユーザー（候補者本人）の実際の行動フロー（企業調査 → 逆質問のカスタマイズ → 面接本番 → 振り返り入力 → 次ステージ準備）とドメインモデルが1:1で一致する。
  - 候補者特有の課題（他社との面接過密、移動時間バッファ不足、面接官ロールに応じた逆質問の使い分け）に特化した高度なビジネスロジック（過剰設計）を正当に構築できる。
- **トレードオフ**:
  - 企業側視点での複数面接官のスコアリングや合否判定ワークフローなどはスコープ外となる。
